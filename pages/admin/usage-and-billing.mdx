## Overview

The Administration panel separates usage metering and accounting operations into three areas:

- **Usage** (`/admin/~/usage`) — token and call volume across LLM, embedding, and tool calls.
- **Costs** (`/admin/~/billing`) — USD charges across every accounting pool (`Included Usage`, `Credit Balance`, `On-Demand Usage`, and `Overflow`), broken down by payer or dimension, plus the complete transaction ledger.
- **Accounting Health** (`/admin/~/billing-health`) — payment-provider status and deferred/pending meter charge sweeps.

<Warning>
Accounting and usage data contains user, account, and consumption information. Export it only when necessary and store it according to your organization's data-handling policy.
</Warning>

## Usage (`/admin/~/usage`)

Use **Administration → Usage** to investigate LLM, embedding, and tool-call activity across the selected **Tenant Context**.

### Period And Filters

Filter chips at the top of the page control:

- **Period** — preset windows or custom date ranges.
- **Provider** — filter to a specific LLM provider.
- **Model** — filter to a specific model.
- **Tenant Context** — controlled from the Administration sidebar.

### Totals And Charts

Four summary cards report totals for the selected period:

- **LLM Tokens**
- **LLM Calls**
- **Embedding Calls**
- **Tool Calls**

Below the summary cards, two time-series charts show running totals of **Tokens** (by token category) and **Calls** (LLM, embedding, and tool calls).

### Breakdown

Group usage by:

- **Project**
- **Tenant**
- **Organization**
- **User**
- **Provider**
- **Model**

Choose columns for call counts, token categories (input, output, thinking, cache-write, cache-read), embedding metrics, identifiers, and metadata. Select a row's metadata action to inspect its structured JSON values, or export the breakdown as CSV.

### Events

The **Events** table exposes the individual metering records behind the aggregates. Filter by event type (**LLM calls**, **Embedding calls**, **Tool calls**, **Storage**, **API calls**, **Compute**, or all types) and select any row to inspect the complete **Metering Event Details** JSON payload.

<Note>
Use the Usage **Events** table for metering evidence. Use the [Audit Log](/pages/admin/operations#audit-log) to investigate administrative and security-relevant actions.
</Note>

## Costs (`/admin/~/billing`)

Use **Administration → Costs** to inspect dollar-denominated charges, pool coverage, payers, and transactions across all accounts in the selected **Tenant Context**.

### Summary Cards And Daily Chart

For the selected period, six summary cards show:

- **Usage Charged** — total USD charged for usage.
- **Included Usage** — amount covered by plan/seat included usage pools.
- **Credit Balance** — amount covered by prepaid or gifted credit balances.
- **On-Demand Usage** — amount billed to on-demand usage pools.
- **Overflow** — usage charged that was not covered by any pool.
- **Credits Added** — total credits added (with net adjustments noted below).

The **Usage Costs by Day** stacked bar chart visualizes daily USD charges broken down by pool (**Included Usage**, **Credit Balance**, **On-Demand Usage**, and **Overflow**).

### Breakdown By Payer Or Dimension

The **Breakdown** table aggregates costs by **Payer** (User, Organization, or Tenant), **Tenant**, **Organization**, **User**, **Project**, **Model**, or **Provider**, showing columns for **Included**, **Credit Balance**, **On-Demand**, **Overflow**, **Usage Charged**, and **Added**.

Click any name in the Breakdown or All Costs table to pin it as an active filter across the page, or export the breakdown to CSV.

### All Costs Ledger

The **All Costs** table lists individual ledger transactions with filters for:

- **Type**: `All`, `LLM calls`, `Tool calls`, or `Credits & adjustments`.
- **Pool**: `All`, `Included Usage`, `Credit Balance`, `On-Demand Usage`, or `Overflow`.
- **Transaction**: `All`, `Additions`, or `Deductions`.

Each row shows the date, payer, type, transaction direction, pool, member, description, USD amount, and the **Pool Balance After** the transaction. To adjust an individual user's, organization's, or tenant's balance directly, open that resource's detail modal on the [Users](/pages/admin/user-access#billing-and-storage), [Organizations](/pages/admin/resources-and-tenants#organization-billing-ai-funding-and-storage-grace), or [Tenants](/pages/admin/resources-and-tenants#5-accounting) page.

## Accounting Health (`/admin/~/billing-health`)

Use **Administration → Accounting Health** to check payment-provider status and settle deferred usage meters:

- **Payment Provider & Payment Enabled**: Shows the configured payment provider and whether external payment processing is enabled.
- **Pending Charges**: Lists usage meters that were recorded but not yet charged to an accounting pool (for example, when a charge was briefly deferred by lock contention). A background sweep processes pending charges every minute, or you can click **Charge Now** to run the sweep immediately.

## Investigation Workflow

1. Confirm the environment and **Tenant Context**.
2. Use **Usage** to identify the actor, resource, provider, model, and metering event.
3. Use **Costs** or the resource's detail view (**Users**, **Organizations**, or **Tenants**) to confirm pool balances and transaction history.
4. Check **Accounting Health** if recent usage events have not yet been applied to a pool.
5. Review the [Audit Log](/pages/admin/operations#audit-log) for administrative balance or limit changes.
