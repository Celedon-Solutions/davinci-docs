## Overview

A model offering connects a shared model definition to the exact model ID and API exposed by an [LLM provider](/pages/admin/llm-provider-configuration).

Open **Administration → LLM Control Plane → Providers**, expand a provider, then select **Add Model** or edit an existing offering.

<Warning>
An offering can save successfully and still be unusable if the provider model ID, API, codec, capabilities, or pricing do not match the real provider. Verify the offering before publishing it.
</Warning>

## Add A Model That Is Not In The List

**Add Model** on a provider only offers models that already have a model definition. When **Discover Models** fails or does not return the model you need, create the definition first:

1. On the **Providers** tab, expand **Default Model Definitions** and select **Add Definition**.
2. Enter the **Model name** and **Publisher**, such as `gpt-image-2` and `openai`. Davinci builds the definition's key from these two values, and the key cannot be changed later.
3. Choose the **Primary model kind** from the [table below](#model-kinds). This decides which routes the model can serve.
4. For an embedding model, enter the **Default vector dimensions** and any other supported dimensions.
5. Under **Limits and capabilities**, set the context window and output limits, and set every capability the model supports to **Supported**. See [Capabilities](#capabilities) for which ones each kind needs.
6. Under **Pricing and metadata**, enter the model's pricing in the form its route requires. See [Workload Pricing Requirements](#workload-pricing-requirements).
7. Select **Create Model**.
8. Expand the provider, select **Add Model**, choose the new definition, and enter the provider's exact **Model ID**, **API**, and **Codec**.

To fix a definition later, including its kind, open it from **Default Model Definitions** and edit it. Every offering that uses the definition inherits the change.

## Model Kinds

The model kind is set on the model definition, and every offering of that model inherits it.

| Kind | Use for | Routes it can serve | Also set |
|---|---|---|---|
| **General** | Chat and instruction models, including multimodal models that read images, audio, or video | Chat, Tools, Summarization, Project names. Reference analysis with Image input, Media analysis with Audio or Video input, and Image generation with Image output | Tools, plus the input capabilities the model has |
| **Embedding** | Text embedding models | Embedding only | Default vector dimensions. Embeddings is set automatically |
| **Image** | Dedicated image generation models | Image generation | Image output, plus SVG output or GIF output if the model produces them |
| **Audio** | Models that only analyze audio | Media analysis | Audio input |
| **Video** | Models that only analyze video | Media analysis | Video input |
| **Realtime** | Live, low-latency voice models | None. Davinci has no realtime route yet | — |

Choose **General** for any chat model, even one that also reads images, audio, or video, and describe its inputs with capabilities instead. A model set to **Audio** or **Video** cannot serve Chat or the tool routes. Chat choices and tool routes never list **Embedding** or **Image** models.

## Offering Fields

### Provider

Select the connection that serves the model. Its configured APIs determine the API choices available to the offering.

### Model

Select the shared model definition. If the model is not in the list, [add a definition](#add-a-model-that-is-not-in-the-list) first. The offering inherits that definition's:

- Model kind.
- Context, output, and image limits.
- Capabilities.
- Base pricing.
- Embedding dimensions.

Use an offering override only when this provider's version differs from the shared definition.

### Offering Name

Enter an optional administrator-facing name. If omitted, Davinci uses the model definition's display name or provider model ID.

Use names that distinguish region, deployment, throughput class, or other meaningful provider differences.

### Model ID

Enter the exact identifier sent to the provider. Examples include a provider model name, deployment name, or Bedrock model identifier.

The value must be non-empty and unique within the provider connection. Do not enter the Davinci display name unless it is also the provider's exact wire model ID.

### API

Select one API configured on the provider. The API determines:

- The request protocol.
- Available codecs.
- Supported workloads.
- Available Chat Control targets.
- Which Advanced options have an effect.

### Codec

The codec converts Davinci's model request to the provider's wire format. Use only the combinations listed below.

### Enabled

An enabled offering can be assigned to profiles when its provider is also enabled. Turn the offering off to prevent new runtime selection.

### Availability

Availability status is one of:

- `available`
- `unavailable`
- `deprecated`
- `unknown`

The optional reason is administrator-facing context.

<Warning>
Availability is informational. Setting an offering to unavailable or deprecated does not block runtime selection. Turn the offering off or archive it when it must not be used.
</Warning>

## API And Codec Compatibility

Every API uses the codec with the same name, except AWS Bedrock Invoke, which needs a codec for the model family.

| API | Codec | Workloads | Chat Controls |
|---|---|---|---|
| `openai.chat_completions` | `openai.chat_completions` | Generation, embeddings | Generic and OpenAI |
| `openai.responses` | `openai.responses` | Generation, embeddings, image generation | Generic and OpenAI |
| `openai.images` | `openai.images` | Image generation only | Not supported |
| `anthropic.messages` | `anthropic.messages` | Generation | Generic and Anthropic |
| `google.generate_content` | `google.generate_content` | Generation, embeddings, image generation | Generic and Google |
| `google.interactions` | `google.interactions` | Generation, embeddings, image generation | Generic and Google |
| `bedrock.invoke` | `anthropic.bedrock.invoke` for Anthropic generation; `amazon.titan.bedrock.invoke` for Titan embeddings | Generation, embeddings | Generic only |

`openai.chat_completions` is the API for OpenAI-compatible services, OpenRouter, Groq, Cerebras, Ollama, and LiteLLM. `anthropic.messages` serves both direct Anthropic and Anthropic On Vertex AI connections.

## Advanced Options JSON

The field accepts a JSON object. Only the options documented in this section are part of the supported public configuration surface.

<Warning>
Do not put credentials, authorization headers, tenant identifiers, user data, or internal URLs in Advanced options JSON. This configuration can be exported and copied between environments.
</Warning>

### Extra Generation Body

Supported generation APIs can receive provider-specific request defaults:

```json
{
  "extraGenerationBody": {
    "store": false
  }
}
```

Use only fields documented by the selected provider and API. Davinci applies canonical request fields after this object, so it cannot reliably replace the selected model, messages, tools, or streaming behavior.

Supported with:

- OpenAI Chat Completions.
- OpenAI Responses.
- Anthropic Messages.
- Google Generate Content.
- Google Interactions.
- Anthropic generation through Bedrock.

It is not consumed by the OpenAI Images or Amazon Titan embedding codecs.

### Omit Generation Parameters

Use this when a model rejects otherwise standard generation parameters:

```json
{
  "omitGenerationParams": [
    "temperature",
    "topP",
    "seed",
    "reasoning"
  ]
}
```

Allowed values are exactly `temperature`, `topP`, `seed`, and `reasoning`:

| Value | APIs where omitting it has an effect |
|---|---|
| `temperature` | OpenAI Chat Completions, OpenAI Responses, Anthropic Messages, Google Generate Content, Google Interactions |
| `topP` | OpenAI Chat Completions, OpenAI Responses, Anthropic Messages, Google Generate Content, Google Interactions |
| `seed` | OpenAI Chat Completions, Google Generate Content, Google Interactions. OpenAI Responses and Anthropic Messages never send a seed |
| `reasoning` | OpenAI Chat Completions, OpenAI Responses, Anthropic Messages, Google Generate Content, Google Interactions |

Anthropic on Bedrock behaves like Anthropic Messages. OpenAI Images and Amazon Titan embeddings ignore this option.

Do not create a Chat Control for a parameter omitted by the offering.

### Output Token Field

Some OpenAI-compatible Chat Completions models expect a different output-token property:

```json
{
  "wireGenerationFields": {
    "maxOutputTokens": "max_completion_tokens"
  }
}
```

`maxOutputTokens` is the only supported mapping key. Its value must be a non-empty wire-field name.

This option applies only to `openai.chat_completions`. OpenAI Responses always uses its Responses API output-token field.

### Prompt Cache

The `promptCache` object accepts different properties per API:

| API | Property | Values |
|---|---|---|
| OpenAI Chat Completions | `key` | Boolean |
| | `mode` | `implicit` or `explicit` |
| | `ttl` | Currently `30m` |
| | `explicitBreakpoints` | Boolean |
| | `breakpointFormat` | `anthropic` or `openai` |
| | `automatic` | Boolean |
| OpenAI Responses | `key` | Boolean |
| | `mode` | `implicit` or `explicit` |
| | `ttl` | Currently `30m` |
| | `explicitBreakpoints` | Boolean |
| Anthropic Messages | `automatic` | Boolean |

For example, on OpenAI Responses:

```json
{
  "promptCache": {
    "key": true,
    "mode": "implicit",
    "ttl": "30m",
    "explicitBreakpoints": true
  }
}
```

When the model or offering declares prompt-caching support and no explicit Prompt Cache object is supplied, Davinci supplies the appropriate default for OpenAI Responses, OpenAI Chat Completions, or Anthropic Messages.

On OpenAI Chat Completions, `explicitBreakpoints` marks the stable start of the prompt so that gateways such as LiteLLM and OpenRouter can cache it with the upstream provider. `breakpointFormat` chooses the marker the model family reads: `anthropic` sends `cache_control` for Claude, including Claude served from Bedrock or Vertex, and `openai` sends `prompt_cache_breakpoint` for GPT models. `automatic` also marks the newest message so a growing conversation stays cached, and `mode` and `ttl` are sent as `prompt_cache_options`.

Davinci turns these on by default for Claude models, identified by an Anthropic publisher or a model ID containing `claude`, and for OpenAI models whose Responses settings use explicit breakpoints. The defaults also fill in any of these properties a Chat Completions Prompt Cache object leaves unset; set `"explicitBreakpoints": false` to send only the cache key. For example, a Claude model through LiteLLM:

```json
{
  "promptCache": {
    "key": true,
    "explicitBreakpoints": true,
    "breakpointFormat": "anthropic",
    "automatic": true
  }
}
```

Gemini models on Vertex AI cache repeated prompt prefixes automatically and need no breakpoints. If a LiteLLM model name routes to more than one deployment, enable LiteLLM's `prompt_caching` pre-call check so repeated prompts reach the deployment that holds their cache.

## Chat Controls

Chat Controls expose safe, predefined model options to users. Use the dedicated editor rather than adding a `chatOptions` property to Advanced options JSON.

The editor rewrites the offering's Chat Controls whenever the offering is saved.

### Choice Control

A choice control contains:

- A unique lowercase key.
- A non-empty label.
- An optional description.
- One supported request target.
- One or more typed choices.
- A default that exactly matches one choice.

Conceptually, a reasoning-effort control is:

```json
{
  "key": "effort",
  "label": "Reasoning effort",
  "description": "Controls how much reasoning the model performs.",
  "target": "openai.reasoning.effort",
  "type": "enum",
  "choices": [
    {
      "value": "low",
      "label": "Low",
      "description": null
    },
    {
      "value": "medium",
      "label": "Medium",
      "description": null
    },
    {
      "value": "high",
      "label": "High",
      "description": null
    }
  ],
  "defaultValue": "medium"
}
```

Choice values can be strings, finite numbers, or booleans. A default must match both the value and its type.

Keys and targets must each be unique within an offering.

### Toggle Control

The editor can create a boolean toggle with separate On and Off labels. Use a toggle only when the selected target and provider explicitly accept boolean values.

The standard provider-specific targets documented below expect string or numeric values, so they should normally use a Choice control.

### Targets

Generic targets work on every generation API: OpenAI Chat Completions, OpenAI Responses, Anthropic Messages, both Google APIs, and Bedrock Invoke. Provider targets work only on the APIs listed.

| Target | APIs | Accepted values |
|---|---|---|
| `generation.reasoning` | All generation APIs | A non-empty, provider-compatible string |
| `generation.maxInputTokens` | All generation APIs | A positive integer up to the effective context limit |
| `generation.maxOutputTokens` | All generation APIs | A positive integer up to the effective output limit |
| `generation.temperature` | All generation APIs | A number from 0 through 2 |
| `generation.topP` | All generation APIs | A number from 0 through 1 |
| `generation.seed` | OpenAI Chat Completions, Google Generate Content, Google Interactions | An integer |
| `openai.reasoning.effort` | OpenAI Chat Completions, OpenAI Responses | `none`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max` |
| `openai.reasoning.mode` | OpenAI Responses | `standard`, `pro` |
| `openai.service-tier` | OpenAI Chat Completions, OpenAI Responses | Depends on the provider and model; Davinci does not check the value |
| `anthropic.output-config.effort` | Anthropic Messages | `low`, `medium`, `high`, `xhigh`, `max` |
| `anthropic.speed` | Anthropic Messages | `standard`, `fast` |
| `google.thinking.level` | Google Generate Content, Google Interactions | `none`, `minimal`, `low`, `medium`, `high`, `xhigh` |
| `google.thinking.budget` | Google Generate Content, Google Interactions | An integer of `-1` or greater |

Any reasoning value other than `none` requires the effective **Reasoning** capability. Anthropic targets are not available when Anthropic is routed through `bedrock.invoke`.

Gemini accepts `xhigh` only on some models, such as Gemini 4 Neon, and rejects the request on the others. Offer it only on an offering whose model accepts it. On the Google APIs, a `generation.reasoning` value of `xhigh` is sent as `high`, so use `google.thinking.level` to offer Gemini's extra-high thinking.

### Derived Context Control

When token pricing defines a long-context threshold below the model's full context window, Davinci can derive a Context control automatically. You do not need to duplicate it manually.

If the offering already defines a control with key `context` or target `generation.maxInputTokens`, the explicit control takes precedence.

## Embedding Execution

Embedding offerings expose:

- **Vector dimensions:** positive integer.
- **Batch size:** positive integer; default 100.
- **Maximum concurrency:** positive integer; default 1.

Vector dimensions inherit from the model definition unless overridden. The named embedding fields take precedence over duplicate Advanced options JSON properties.

An embedding route must target an offering with the Embeddings capability.

Embedding pricing must be input-only token pricing:

- Pricing type is per token.
- Input price is zero or greater.
- Output price is zero.

<Warning>
Changing vector dimensions changes the shape of generated embeddings. Existing project vectors must be regenerated after the new configuration is published.
</Warning>

## Limit Overrides

Offering limits inherit from the model definition.

- **Context window tokens:** positive integer.
- **Maximum output tokens:** positive integer.
- **Maximum image count:** non-negative integer.

Editing a value creates an override. Use **Clear override** to return to inheritance.

Do not enter a larger value unless the exact provider offering supports it.

## Capabilities

Capabilities describe what a model can do, and they decide which routes can use it. Each capability is **Inherit / unknown**, **Supported**, or **Not supported**. The model definition sets them, and an offering can override them.

**Unknown is not the same for every capability.** Tools, Streaming, and Structured output count as supported unless set to **Not supported**. Every other capability counts only when set to **Supported**, so set them explicitly when you add a model by hand.

| Capability | What it enables | When it is not supported |
|---|---|---|
| **Tools** | The Simple, Standard, and Complex tool routes, and tool calls from chat | The offering is not listed for tool routes, and any request that includes tools fails |
| **Streaming** | Streamed responses in chat and the agent's tool loop | Streamed calls fail. Leave it on unless the provider cannot stream |
| **Structured output** | JSON-schema responses, which many tools request | Requests that ask for structured output fail |
| **Image input** | The Reference analysis route, and images in chat and tool calls | The offering is not listed for Reference analysis, images in the conversation are omitted, and tool calls that send images fail |
| **Image output** | The Image generation route, together with a codec that supports image generation | The offering is not listed for Image generation |
| **Prompt caching** | Davinci's default prompt cache settings on OpenAI Responses, OpenAI Chat Completions, and Anthropic Messages, and the cache pricing fields | No prompt cache settings are sent unless set in [Advanced options JSON](#prompt-cache) |
| **Reasoning** | Reasoning Chat Controls and generation defaults with any value other than `none` | Saving or publishing a reasoning control with values other than `none` fails |
| **Audio input** | The Media analysis route, and audio in the conversation | Audio is omitted from requests |
| **Video input** | The Media analysis route | The offering is not listed for Media analysis unless it has Audio input |
| **SVG output** | SVG requests on the Image generation route. Requires composite pricing with a per-token component, because the provider also bills the tokens its SVG authoring model spends | SVG requests are not sent to the offering |
| **GIF output** | Animated GIF requests on the Image generation route | GIF requests are not sent to the offering |
| **Embeddings** | The Embedding route. Set automatically for the Embedding kind | The offering is not listed for Embedding |
| **Audio output**, **Video output** | Recorded for reference; no Davinci route uses them yet | No effect |

[Verification](/pages/admin/llm-control-plane#verification) also follows capabilities: it adds tool-calling, image-input, and embedding checks when those are **Supported**, and streaming and structured-output checks unless those are **Not supported**.

Use **Supported** only when the provider offering actually implements the capability through the selected API and codec. An offering override changes which routes can select the offering, but it cannot add a capability the provider lacks.

## Runtime Controls

An offering's **Runtime controls** section inherits its defaults from the selected [LLM provider](/pages/admin/llm-provider-configuration#runtime-defaults) unless overridden on the offering:

| Field | Key | Platform default | Controls |
|---|---|---|---|
| **Request / first-token timeout (ms)** | `timeoutMs` | `60000` | Wait for the first streamed content or a non-streaming response |
| **Max attempts (initial + retries)** | `retryCount` | `5` | Total attempts before failing or falling back. `1` means no retries |
| **Stream idle timeout (ms)** | `streamIdleTimeoutMs` | `90000` | Longest gap allowed between streamed chunks |
| **Stream absolute timeout (ms)** | `streamAbsoluteTimeoutMs` | `300000` | Longest total time for one stream attempt |
| **Max request size (bytes)** | `maxRequestSizeBytes` | None | Payload size above which older images or messages are trimmed |

Each field inherits the provider's value with the same key, except `timeoutMs`, which inherits the provider's `defaultTimeoutMs`. If the provider does not set a value either, the platform default applies.

Editing any field activates an offering-level override; use **Clear overrides** in the Runtime controls header to return to inheriting from the provider. Connection-wide concurrency (`Max concurrent requests / replica`) is configured on the provider.

## Pricing Overrides

All prices are in USD. An offering inherits its model definition's base pricing until an override is activated.

### Per Token

Configure:

- Input USD per 1 million tokens.
- Output USD per 1 million tokens.
- Optional cache-write USD per 1 million tokens.
- Optional cache-read USD per 1 million tokens.

Example values:

```json
{
  "kind": "per_token",
  "inputUsdPer1MTokens": 1,
  "outputUsdPer1MTokens": 5,
  "cacheWriteUsdPer1MTokens": null,
  "cacheReadUsdPer1MTokens": null,
  "longContext": null
}
```

### Long-Context Token Pricing

Configure a threshold, input rate, and output rate together:

```json
{
  "thresholdInputTokens": 200000,
  "inputUsdPer1MTokens": 2,
  "outputUsdPer1MTokens": 8,
  "cacheWriteUsdPer1MTokens": null,
  "cacheReadUsdPer1MTokens": null
}
```

A request above the threshold uses the long-context rates for the entire request.

If regular cache rates are configured, provide the corresponding long-context cache rates.

### Per Image

Configure at least one image rate:

```json
{
  "kind": "per_image",
  "rates": [
    {
      "resolution": "1K",
      "quality": null,
      "usdPerImage": 0.04
    }
  ],
  "inputTextUsdPer1MTokens": null,
  "inputImageUsdPerImage": null
}
```

The current editor provides 1K, 2K, and 4K output rates plus optional text-input and input-image costs.

### Per Image-Output Token

```json
{
  "kind": "per_image_token",
  "estimator": "openai_grid",
  "outputUsdPer1MTokens": 10,
  "inputTextUsdPer1MTokens": null,
  "inputImageUsdPer1MTokens": null,
  "cachedInputUsdPer1MTokens": null
}
```

Estimator values are:

- `openai_grid`
- `provider_reported`

### Per Second

Configure either or both media rates:

```json
{
  "kind": "per_second",
  "audioUsdPerSecond": 0.001,
  "videoUsdPerSecond": null
}
```

### Composite Pricing

Composite pricing combines different atomic pricing kinds. Enter a JSON array in the Composite components field:

```json
[
  {
    "kind": "per_token",
    "inputUsdPer1MTokens": 1,
    "outputUsdPer1MTokens": 5
  },
  {
    "kind": "per_image",
    "rates": [
      {
        "resolution": "1K",
        "quality": null,
        "usdPerImage": 0.04
      }
    ]
  }
]
```

The array must contain at least one component and can contain only one component of each pricing kind. Composite components cannot contain another composite.

### Workload Pricing Requirements

- Image-generation assignments require per-image, per-image-token, or compatible composite image pricing.
- Embedding assignments require input-only per-token pricing with zero output pricing.
- Other model calls use the effective model or offering pricing for usage calculation.

Review [Usage And Billing](/pages/admin/usage-and-billing) after publishing a pricing change.

## Offering Checklist

Before publishing:

1. Confirm the provider and exact Model ID.
2. Confirm that the API and codec are compatible.
3. Remove unsupported generation parameters.
4. Review inherited and overridden limits, capabilities, and pricing.
5. Validate every Chat Control target and default.
6. Confirm embedding dimensions and pricing where applicable.
7. Turn the offering on.
8. Run verification against the draft.
9. Confirm profile routes and publish from the [LLM Control Plane](/pages/admin/llm-control-plane#publish-changes).
