## Overview

Use **Administration → Settings** (`/admin/~/settings`) to configure deployment-wide behavior. The page includes authentication providers, access feature flags, platform defaults, new-user accounting and funding defaults, and infrastructure information.

<Warning>
Authentication and access-policy changes can lock users out of Davinci. Keep a tested system-administrator recovery account and change one authentication layer at a time.
</Warning>

## Infrastructure And Deployment

The read-only Infrastructure section shows the deployment domain, Davinci version, and environment when that information is available.

**Deployment Name** controls the name presented for this Davinci installation.

## Feature Flags

The Feature Flags section on the Settings page controls deployment-wide access and integration switches:

- **Disable Public Sign-up** prevents users from registering themselves.
- **Admin-Provisioned Only** restricts platform access to admin-created accounts. Pair it with **Disable Public Sign-up** when self-service registration must be blocked.
- **Enable Bridge Access** permits bridge relay connections for external integrations.
- **Enable API Keys** permits Personal Access Tokens and API-key authentication across the deployment.

<Info>
Product and modeling feature entitlements (such as Scratch Pad, Journeys, CAD Objects, Onshape Connect, Personal Access Tokens, Simulation options, and project/collaborator limits) are managed through [Entitlement Groups](/pages/admin/user-access#entitlement-groups-administration--groups) (`/admin/~/groups`, where the `base` group sets the system baseline for all users) and per-user or per-organization [Entitlements](/pages/admin/user-access#entitlements) overrides.
</Info>

### API-Key Kill Switch

Disabling **Enable API Keys** is a deployment-wide credential kill switch. Individual user or group entitlements do not override it.

To allow programmatic access, both must be enabled:

1. The global **Enable API Keys** toggle on `/admin/~/settings`.
2. The user's resolved **Personal Access Tokens** entitlement under [Entitlement Groups or User Entitlements](/pages/admin/user-access#entitlements).

See [Personal Access Tokens](/pages/api/personal-access-tokens) for user-facing credential guidance.

## Single Sign-On (SSO)

The SSO section configures an OpenID Connect provider.

### Connection

Configure:

- **Enable SSO**.
- **SSO Only**, which disables password login as a normal sign-in option.
- **Discovery URL**.
- **Client ID** and **Client Secret** (stored encrypted at rest; falls back to the `OIDC_CLIENT_SECRET` environment variable if left blank).
- **Redirect URI**.
- **Post-logout redirect URI**.
- **Scope** (for example, `openid profile email`).
- **SSO Message** displayed to users.

The redirect and post-logout URLs must also be allowed by the identity provider.

### Claim Mapping

Map provider claims for:

- **Email Claim**.
- **First Name Claim**.
- **Last Name Claim**.
- **Display Name Claim**.
- **Groups Claim**.

The email claim must resolve to the address Davinci should use for the account.

### Group Access Policy

Add one allowed group per row (`+ Add group`). An empty list allows any successfully authenticated SSO user. Group matching is case-insensitive and supports `*` wildcards (for example, `davinci-user` or `CN=DV-*`).

The optional **Deny Message** is shown on the login page when a user authenticates successfully but does not satisfy the group policy.

### Secret Handling

SSO client secrets are stored securely and are never returned to the browser. When editing SSO, leave the secret field blank to preserve the current secret; entering a value replaces it.

<Warning>
Do not enable **SSO Only** until the discovery URL, callback, claims, group policy, and at least one administrator account have been tested end to end.
</Warning>

## Directory Authentication (LDAP)

The LDAP section supports saving a draft configuration while LDAP is disabled. Enabling LDAP requires a successful connection test.

### Connection

Configure:

- **Server URL**.
- **Base DN**.
- **Bind DN** and **Bind Password**.
- **User Search Filter**.
- **Login-page message**.

Use encrypted `ldaps://` transport whenever possible. **Verify TLS Certificate** should remain enabled unless the directory uses a certificate chain you explicitly trust another way. **Allow Insecure Transport** permits plaintext `ldap://` connections and should be limited to controlled test environments.

### Account Provisioning

**Directory email domains** controls when Davinci searches LDAP for an email that does not already have an account:

- `*` allows a lookup for any email domain.
- A comma-separated list limits lookup to those domains.
- An empty value disables login-time directory lookup, so an administrator must provision accounts.

### Attribute Mapping

Configure the LDAP attributes used for:

- **Username**.
- **Email**.
- **Display name**.
- **Stable unique ID**.
- **Group Search Base** and **Group Member Attribute**.

<Warning>
The unique ID attribute links a directory entry to an existing Davinci account. Changing it after accounts are linked can break those links.
</Warning>

### Group Access Policy

Add one allowed LDAP group or distinguished name per row (`+ Add group`). An empty list allows any authenticated directory user. Matching is case-insensitive and supports `*` wildcards.

Use the **Deny Message** to explain how an excluded user should request access without disclosing directory internals.

### Save And Test

The LDAP workflow is:

1. Enter or update the configuration.
2. Select **Test connection**.
3. Resolve any connection, bind, search, TLS, or policy error.
4. Select **Save LDAP**.
5. If enabling LDAP for the first time, review the user-migration picker.

Changing an LDAP field invalidates the previous successful test. LDAP bind passwords are never returned to the browser; leave the password field blank to preserve the current value.

## Switch Existing Users To LDAP

When LDAP is enabled, select **Switch users to LDAP...** to migrate selected active users.

The picker:

- Preselects password users whose email matches the configured directory domains.
- Excludes accounts already linked or pending LDAP.
- Supports search and select-all for the visible results.

For each selected user, Davinci verifies that a directory entry exists before changing authentication. A matching user is linked and their Davinci password is removed. A user without a matching entry is skipped and left unchanged. One failed user does not stop the rest of the batch.

To recover an incorrectly linked account, use [Unlink LDAP](/pages/admin/user-access#unlink-ldap).

## Multi-Factor Authentication (MFA)

MFA settings control TOTP enrollment:

- **Enable MFA** allows users to enroll.
- **Require MFA** forces all users to enroll.
- **Recovery Method** selects **Admin Reset** or **Recovery Codes**.

Requiring MFA changes the sign-in requirements for the whole deployment. Communicate the rollout and recovery process before enabling it. Administrators can clear an individual enrollment from [Users, Entitlements, And Access](/pages/admin/user-access#reset-mfa).

## OAuth Providers

The OAuth section registers a provider (**Google**, **GitHub**, or **Microsoft**) and its **Client ID**. Configured entries can be removed from the list. Ensure the corresponding callback and credentials are configured in the deployment environment.

## Platform Defaults

- **Skip Email Verification** — when enabled, new users are not required to verify their email address.
- **Auto-Accept Project Invites** — automatically adds existing users to projects instead of sending an invitation.
- **Auto-Accept Organization Invites** — automatically adds existing users to organizations instead of sending an invitation.
- **Business Mailing Address** — physical address shown in administrative email footers for CAN-SPAM compliance. Keep it accurate before sending campaigns from [Notifications](/pages/admin/operations#notifications).

## New User Defaults And Accounting Policy

The **New User Defaults** section configures accounting, funding, and storage defaults for newly provisioned accounts and deployment-wide usage display:

- **Free Plan Included Usage (USD)** — one-time Included Usage gift (in USD) granted to new users on the deployment's LLM keys.
- **Default User On-Demand Limit (USD per period)** — on-demand usage allowed per period after a user's credit balance runs out (leave blank to disable on-demand usage for new users, or toggle **Unlimited**).
- **Usage Period Reset** — configures the **Day of Month** (`1`–`31`), **Hour (0–23)**, and **Timezone** when internal on-demand balances and member spend limits reset (short months reset on their last day).
- **Organization AI Funding** — controls whether organizations can pay for AI usage in their projects:
  - `Off: members always pay`
  - `Organizations can pay from their credit balance and on-demand usage`
  - `Organizations can also use their own provider API keys`
- **Show Included Usage as Percentage** — when enabled, shows users their Included Usage as a percentage of their plan's allocation rather than a dollar amount (while accounting continues to track usage in dollars).
- **LLM Price Margin** — gross margin fraction in `[0, 1)` applied to raw provider cost (`price = cost / (1 - margin)`). Set to `0.0` for no markup, or e.g. `0.2` for a 20% gross margin.
- **Default Storage Amount** — default storage limit for new users in GB (leave blank for unlimited).

## Allowed Email Domains

Enter a comma-separated allowlist of domains that may register (for example, `example.com, acme.org`), or use `*` to allow any domain.

Email-domain policy is separate from SSO or LDAP group policy. A deployment can use both domain routing and provider-side access restrictions.
