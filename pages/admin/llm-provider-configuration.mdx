## Overview

An LLM provider is a connection from Davinci to a hosted model service, cloud platform, local runtime, or compatible gateway. A provider can expose one or more APIs, and each API can serve several [model offerings](/pages/admin/llm-offering-configuration).

Open **Administration → LLM Control Plane → Providers**, then select **Add Provider** or edit an existing connection.

<Warning>
The form can display authentication methods and APIs that do not work together. Use the supported recipes on this page rather than assuming every dropdown combination is valid.
</Warning>

## Provider Fields

### Provider Name

Enter a non-empty administrator-facing name. Davinci creates a stable lowercase provider key from the initial name. The key is used to identify the connection in profiles, exports, and runtime configuration.

Use a distinct name when the same vendor has separate regions, credentials, endpoints, or tenant scopes.

### Base URL

Enter an absolute provider URL, including `http://` or `https://`.

- Hosted provider recipes below include their standard URL.
- OpenAI-compatible and LiteLLM connections require a reachable URL.
- Cloud SDK connections such as Bedrock and Vertex normally leave it blank.
- Do not include a username, password, API key, or bearer token in the URL.

For a private or local provider, the URL must be reachable from the Davinci runtime environment. `localhost` refers to that runtime environment, not necessarily the machine running your browser.

### Authentication Method

Choose one method. The [provider recipes](#supported-provider-recipes) list which methods each provider supports.

| Method | Field to fill in | Enter | Example |
|---|---|---|---|
| **API key** | **Credential / API Key** | The secret itself. When editing, leave it blank to keep the stored value | — |
| **Environment variable** | **API Key Environment Variable** | The variable name only, never the secret | `PROVIDER_API_KEY` |
| **Application default credentials** | None; the cloud SDK finds the workload identity or credential chain | — | — |
| **Token file** | **Token File Path** | An absolute path to a file that contains the token | `/run/secrets/provider-token` |
| **No authentication** | None | — | — |

Environment variables and token files must be available to the Davinci runtime in every environment where the connection is used.

<Warning>
Use only the dedicated credential field for a provider secret. Never put a secret in Additional options JSON, a URL, a header, an exported configuration, or a screenshot.
</Warning>

### Region / Location

Enter the cloud region used by the provider, such as `us-east-1`, `us-central1`, or another provider-supported location.

- Bedrock uses the region for its AWS clients.
- Google Vertex uses `location` from Additional options JSON when present, then falls back to this field.
- Anthropic on Vertex uses this field as its Vertex region.

### Cloud Project ID

Application-default credentials with a Google or Anthropic Vertex API require a Google Cloud project ID. Enter the project identifier, not its display name.

The named Cloud Project ID field overrides a duplicate `projectId` in Additional options JSON.

### Allowed APIs

Select one or more APIs exposed by the connection:

| API | Protocol | Workloads |
|---|---|---|
| `openai.responses` | OpenAI Responses | Generation, embeddings, image generation |
| `openai.chat_completions` | OpenAI Chat Completions | Generation, embeddings |
| `openai.images` | OpenAI Images | Image generation |
| `anthropic.messages` | Anthropic Messages | Generation |
| `google.generate_content` | Google Generate Content | Generation, embeddings, image generation |
| `google.interactions` | Google Interactions | Generation, embeddings, image generation |
| `bedrock.invoke` | AWS Bedrock Invoke | Anthropic generation, Amazon Titan embeddings |

Many gateways and hosted services implement the OpenAI and Anthropic APIs, often several at once. Select only APIs actually implemented by the endpoint. An endpoint that supports OpenAI Chat Completions does not automatically support OpenAI Responses or Images.

### Default API

When more than one API is selected, choose a default. The default must also appear in **Allowed APIs**.

Each model offering still selects its exact API and compatible codec.

### Runtime Defaults

The **Runtime defaults** section configures default concurrency, retry budget, and timeout limits inherited by all model offerings on the provider unless an offering overrides them:

| Field | Key | Default | Controls |
|---|---|---|---|
| **Request / first-token timeout (ms)** | `defaultTimeoutMs` | `60000` | Wait for the first streamed content or a non-streaming response |
| **Max attempts (initial + retries)** | `retryCount` | `5` | Total attempts before failing or falling back. `1` means no retries |
| **Max concurrent requests / replica** | `maxConcurrentPerConnection` | None | Connection-wide concurrency cap per Design Engine replica |
| **Stream idle timeout (ms)** | `streamIdleTimeoutMs` | `90000` | Longest gap allowed between streamed chunks |
| **Stream absolute timeout (ms)** | `streamAbsoluteTimeoutMs` | `300000` | Longest total time for one stream attempt |
| **Max request size (bytes)** | `maxRequestSizeBytes` | None | Payload size above which older images or messages are trimmed |

## Per-API URL Settings

Advanced connection settings provide one URL field per selected API. Enter:

- A relative path such as `/v1` to append it to the Base URL.
- A complete absolute URL to override the Base URL for that API.
- Nothing to use the Base URL unchanged.

For example, Base URL `https://llm.example.com` with extension `/v1` resolves to:

```text
https://llm.example.com/v1
```

Do not repeat an extension already included in the Base URL.

### Gateways With A Path Per API

Some gateways serve each API under its own path. Configure one provider with every API the gateway implements, set the Base URL to the shared root, and give each API its own extension. The Anthropic SDK appends `/v1/messages` itself, so Anthropic extensions stop before `/v1`. These setups combine APIs beyond a single recipe, so verify each API separately.

**Ask Sage**, with Base URL `https://api.asksage.ai/server` (the host differs per Ask Sage instance):

| API | URL extension | Resolves to |
|---|---|---|
| `openai.responses`, `openai.chat_completions` | `/openai/v1` | `https://api.asksage.ai/server/openai/v1` |
| `anthropic.messages` | `/anthropic` | `https://api.asksage.ai/server/anthropic` |

Ask Sage's Gemini-style route at `/google/v1beta` authenticates with a non-standard `x-access-tokens` header that Davinci's Google APIs do not send, so do not add a Google API to an Ask Sage provider.

**Amazon Bedrock Mantle**, with Base URL `https://bedrock-mantle.us-east-1.api.aws` and an Amazon Bedrock API key. Mantle is an OpenAI- and Anthropic-compatible endpoint, separate from the **AWS Bedrock** recipe and its `bedrock.invoke` API.

| API | URL extension | Serves |
|---|---|---|
| `openai.responses`, `openai.chat_completions` | `/v1` | Most models, including gpt-oss, and the model list for every model |
| `anthropic.messages` | `/anthropic` | Claude models |

Mantle serves OpenAI GPT models, and some others, under `/openai/v1` instead of `/v1`. A provider has one URL per API, so add a second Mantle provider whose OpenAI APIs use the full URL `https://bedrock-mantle.us-east-1.api.aws/openai/v1`, and add those models to it with **Add Model**. Check a model's card in the Bedrock console for which path it uses.

<Warning>
**Known issue: discovery and health checks depend on the model-list endpoint.** **Discover Models** lists models only from the default API's URL, and the provider health check calls the model-list endpoint of every selected API. When a gateway keeps its model list on a different path from some of its inference routes, discovery fails or returns the wrong set, and the health check reports the provider unhealthy even though inference works.

For example, Mantle lists every model at `/v1/models`, while `/openai/v1/models` returns `404`. A Mantle provider whose default API points at `/openai/v1` cannot discover models and fails its health check.

To work around it, set the **Default API** to one whose URL serves the model list. On a provider where no API path has a model list, add models manually with **Add Model** and confirm them with [verification](/pages/admin/llm-control-plane#verification) instead of the health check.
</Warning>

## Additional Options JSON

The field accepts a JSON object. Named form fields take precedence over duplicate JSON properties.

### Default Invocation Timeout

```json
{
  "defaultTimeoutMs": 60000
}
```

`defaultTimeoutMs` must be a positive number of milliseconds. It is used when a model offering does not define its own timeout. The default is 60,000 milliseconds.

### Default HTTP Headers

```json
{
  "defaultHeaders": {
    "X-Application-Name": "Davinci",
    "X-Environment": "production"
  }
}
```

Header names and values should be strings. Default headers are supported by every connection that uses an OpenAI API and by direct Anthropic connections. Anthropic On Vertex AI does not send them.

<Warning>
Default headers can be included in portable configuration. Do not put authorization values, tokens, session identifiers, or other secrets in this object.
</Warning>

### Vertex Location

```json
{
  "location": "us-central1"
}
```

Use `location` when the Vertex location should differ from or explicitly override the provider's Region / Location field.

The Cloud Project ID should normally be entered in its named field. Its corresponding JSON property is `projectId`.

### Provider-Wide Request Defaults

Generation APIs can accept provider-specific request defaults:

```json
{
  "extraGenerationBody": {
    "store": false
  }
}
```

These values apply to every compatible offering on the provider. Use [offering-level options](/pages/admin/llm-offering-configuration#advanced-options-json) when only one model should receive them.

Davinci applies its canonical request fields after these defaults. Provider-wide defaults cannot reliably replace fields controlled by Davinci, such as the selected model or conversation messages.

The merge is shallow: an offering's `extraGenerationBody` replaces the provider-level object rather than merging individual nested fields.

### Complete Example

```json
{
  "defaultTimeoutMs": 60000,
  "defaultHeaders": {
    "X-Application-Name": "Davinci"
  },
  "extraGenerationBody": {
    "store": false
  }
}
```

Only include options required by the selected provider. Unlisted properties should not be assumed to have an effect.

## Supported Provider Recipes

| Provider | Base URL | Authentication | APIs |
|---|---|---|---|
| **OpenAI** | `https://api.openai.com/v1` | API key, environment variable | Responses (recommended default), Images, Chat Completions |
| **OpenAI-Compatible** | Required | API key, environment variable, none | Whichever OpenAI APIs the endpoint implements |
| **Anthropic** | `https://api.anthropic.com` | API key, environment variable | Anthropic Messages |
| **Google Gemini** | `https://generativelanguage.googleapis.com` | API key, environment variable | Google Generate Content, Google Interactions |
| **AWS Bedrock** | Blank unless overriding the endpoint | Application default credentials | AWS Bedrock Invoke |
| **Google Vertex AI** | Blank unless overriding the endpoint | Application default credentials | Google Generate Content |
| **Anthropic On Vertex AI** | Blank unless overriding the endpoint | Application default credentials | Anthropic Messages |
| **OpenRouter** | `https://openrouter.ai/api/v1` | API key, environment variable | OpenAI Chat Completions |
| **Groq** | `https://api.groq.com/openai/v1` | API key, environment variable | OpenAI Chat Completions |
| **Cerebras** | `https://api.cerebras.ai/v1` | API key, environment variable | OpenAI Chat Completions |
| **Ollama** | A URL reachable from the Davinci runtime | None | OpenAI Chat Completions |
| **LiteLLM** | Required | API key, environment variable, token file, none | OpenAI Chat Completions |

Every recipe accepts `defaultTimeoutMs` in Additional options JSON. `defaultHeaders` works on any connection that uses an OpenAI API and on direct Anthropic. The Vertex recipes also accept `projectId` and `location`.

Enable only the APIs your offerings use. Recipe-specific notes:

- **OpenAI-Compatible:** verify each selected API separately. Compatibility with Chat Completions does not prove compatibility with Responses, Images, tool calls, structured output, or usage reporting.
- **AWS Bedrock:** the region defaults to `us-east-1`. Offerings need a model-specific codec: Anthropic on Bedrock for Anthropic generation models, or Amazon Titan for Titan embeddings. Models are normally added manually rather than discovered.
- **Google Vertex AI and Anthropic On Vertex AI:** a **Cloud Project ID** is required. The region defaults to `us-central1` for Google Vertex AI and `us-east5` for Anthropic On Vertex AI. Prefer the named **Cloud Project ID** and **Region / Location** fields over JSON. The equivalent JSON is:

  ```json
  {
    "projectId": "example-cloud-project",
    "location": "us-central1"
  }
  ```

- **OpenRouter:** if attribution headers are required, add them to `defaultHeaders`, using your approved public application URL:

  ```json
  {
    "defaultHeaders": {
      "HTTP-Referer": "https://davinci.example.com",
      "X-Title": "Davinci"
    }
  }
  ```

- **Ollama:** the Base URL must be reachable from the Davinci runtime. The browser machine's `localhost` is usually not.

## Save And Verify

After saving a provider:

1. Confirm the endpoint, authentication method, APIs, and scope.
2. Run the provider health check.
3. Discover models when the provider supports reliable discovery, or add an offering manually.
4. Configure and [verify each model offering](/pages/admin/llm-control-plane#verification).
5. Publish only after reviewing all affected profiles and routes.

A successful provider health check confirms connection-level access. It does not prove that every model ID, capability, codec, or pricing configuration is correct.

## Portability

Exports never contain provider credentials. Environment-variable names and token-file paths are also omitted.

After importing configuration into another deployment:

- Re-enter required credentials.
- Reconfigure environment-variable or token-file authentication.
- Verify network reachability.
- Run health and model-offering verification.
- Publish only after the destination runtime accepts the configuration.
