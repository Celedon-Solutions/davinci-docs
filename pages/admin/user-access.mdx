## Overview

Use **Administration → Users** (`/admin/~/users`) to manage accounts across the deployment, and **Administration → Groups** (`/admin/~/groups`) to manage the entitlement groups that control which features, limits, and LLM profiles users and organizations receive.

The separate **Roles** page (`/admin/~/roles`) provides a system-role catalog and direct role lookup. It is hidden on self-hosted deployments; the user detail view remains the primary place to inspect and manage an individual account.

<Warning>
User administration can expose personal information and temporary credentials. Share exports and credentials only through approved secure channels.
</Warning>

## Find And Review Users

Search by name or email, then filter by:

- Account status.
- Tenant.
- System or tenant role.
- Email-verification state.
- MFA state.
- Sign-in method, including password, OAuth, OIDC, or LDAP.

Select **Columns** to include identifiers, tenant, seat type, sessions, sign-in method, project count, storage, and other account fields. Column choices are remembered in the browser.

Select **Export** to download the complete filtered result set with the currently selected columns. Treat the CSV as sensitive because it can contain user identifiers, email addresses, tenant membership, authentication state, and usage-related data.

## Provision A User

Select **Add User** and provide:

1. The user's email address.
2. An optional display name.
3. The authentication type (**Password**, **OAuth**, **SSO / OIDC**, or **LDAP / Directory**).
4. A provider name when required by OAuth or OIDC.
5. Whether Davinci should email password credentials.

The account is created in the tenant selected by the Users page tenant filter. If that filter is empty, the current **Tenant Context** is used. Verify the target shown in the form before submitting.

### Authentication Types

- **Password** creates a Davinci password identity and a temporary password.
- **OAuth** associates the account with a named OAuth provider.
- **SSO / OIDC** associates the account with the configured identity provider.
- **LDAP / Directory** prepares the account for directory authentication.

When email delivery is selected for a password account, Davinci attempts to send the temporary password to the user. If delivery is not selected or does not succeed, the temporary password is displayed once for manual delivery.

<Warning>
Copy a displayed temporary password before closing the result. Do not place it in tickets, documentation, or ordinary chat. The user is required to change it after signing in.
</Warning>

For deployment-wide provider setup and allowed email domains, see [System Settings And Authentication](/pages/admin/system-settings-authentication).

## Bulk Provision Users

Select **Bulk Add** to create up to 200 accounts at once with the same authentication type, tenant, optional admin entitlement group grant, and optional starting credit balance.

Enter one account per line in either form:

```text
user@example.com
user@example.com, Display Name
```

Configure:

- **Auth Type** and optional **Provider Name**.
- **Admin group grant** — optionally assign all created users to a user entitlement group (or leave as `None (default group only)` so they receive `base` defaults).
- **Credit Balance** — optional one-time starting credit balance entered in **Credits** or **Dollars ($)**. The preview converts between the two using the current credit rate and applies the same amount to each created user.
- **Email credentials to users** — whether to email temporary passwords automatically.

A failure for one entry does not prevent the other entries from being processed. Review the result table for created and failed accounts, email-delivery results, and any temporary passwords that require manual delivery.

## Entitlement Groups (`Administration → Groups`)

Entitlement groups (`/admin/~/groups`) control which features, limits, and LLM profiles users and organizations receive across the platform.

### How Entitlements Resolve

Every entitlement key resolves in four steps:

1. **Subject Override** — A per-user or per-organization override set on that subject's **Entitlements** tab beats every group.
2. **Active Groups** — Across all active groups a subject belongs to, the **most permissive** value wins (`On` beats `Off`, `Unlimited` beats numeric limits, largest numeric limit wins, and the highest-ranked LLM profile wins). Every user automatically belongs to the `base` group.
3. **System Catalog Default** — Used whenever a key is left at *Catalog default* across all of the subject's active groups.
4. **License & Seat Ceiling** — The deployment/tenant license and read-only seat status clamp the final effective result.

### Managing Entitlement Groups

The **Groups** table lists each group's name and key, target subject type (**Users** or **Organizations**), management source (`system`, `billing`, or `admin`), active member count, and a summary of its configured entitlements.

- **System baseline (`base`)**: Every user is in `base`. Editing `base` changes the default limits, LLM profile, and features for all users who do not have a more permissive group or override.
- **Billing-managed groups**: Plans such as `core`, `max`, `team` (Group plan), and `org_owner` are assigned automatically when subscriptions change, though administrators can inspect or customize the entitlements those groups grant.
- **Admin-managed groups**: Click **New group** to create a custom group with a lowercase key (for example, `pilots` or `power_users`), name, description, and target (**Users** or **Organizations**). Admin-created groups can be archived when no longer needed.

Click any group row to open its detail modal and configure:

- **Limits** — Set each limit (such as maximum owned projects or maximum collaborators per project) to **Catalog default**, **Custom limit**, or **Unlimited**.
- **Options** — For user groups, select the **LLM profile** granted by the group (or leave at **Catalog default**).
- **Features** — Set feature flags and rollouts (such as Scratch Pad, Journeys, CAD Objects, Onshape Connect, Personal Access Tokens, Simulation options, or organization AI funding) to **Catalog default**, **On**, or **Off**.
- **Members** — View all users or organizations currently in the group, how they were added (`Default group`, `Billing plan`, `Tenant membership`, `Trial`, or `Admin grant`), and when their membership ends.

## User Details

Select a user row on `/admin/~/users` to open the User Details modal, which is organized into seven tabs: **Account**, **Entitlements**, **Sessions**, **Billing**, **Storage**, **Roles**, and **Projects**.

### Account

The **Account** tab shows identity, avatar, status, seat type (**Full** or **Read-only**), tenant, sign-in, verification, and session information. Administrators can:

- Update the **Display Name** or remove the user's custom avatar image.
- **Move** the user to a different tenant (or back to `Default (Standalone)`).
- Mark an unverified email address as **Verified**.
- **Reset Password** or **Reset MFA**.
- **Unlink LDAP** if the account is linked to a directory.
- **Deactivate**, **Reactivate**, or **Permanently Delete** (`Delete Forever`) the account.

### Entitlements

The **Entitlements** tab shows every resolved limit, option, and feature for the user along with its source (`Catalog default`, `Group: <name>`, `Override`, or `Platform` ceiling). From this tab, administrators can:

- **Seat type**: Switch the user between a **Full** seat and a **Read-only** seat (read-only seats can view, export, and comment, but cannot edit models or use AI).
- **Group memberships**: View active group memberships and grant a new **Admin grant** group membership with an optional expiration date, or remove an existing admin grant.
- **Trial**: Grant the user a time-limited trial of any user group (for example, `max`) with a duration in days and an optional trial credit balance in USD, or **Revoke trial** on an active trial.
- **Limits, Options, and Features Overrides**: Set or **Clear** a per-user override on any settable limit (such as max owned projects or collaborators), option (such as the user's **LLM profile**), or feature flag (such as Scratch Pad, Onshape Connect, or Personal Access Tokens).

<Note>
Per-user **Personal Access Token** entitlement does not override the deployment-wide **Enable API Keys** kill switch in System Settings. Both must allow access. See [Personal Access Tokens](/pages/api/personal-access-tokens).
</Note>

### Sessions

The **Sessions** tab lists active sessions, including device label, IP address, creation time, last use, and expiration. You can revoke one session or all sessions.

Revocation prevents the selected session from refreshing its access token. Use it when a device is lost, a credential may be compromised, or an access change should take effect promptly.

### Billing And Storage

The **Billing** tab shows the user's accounting pools (**Included Usage**, **Credit Balance**, and **On-Demand Usage**), funding scope (**Individual** vs. **Group Member**), and usage period start. Administrators can:

- **Adjust Balance**: **Add** (`credit`) or **Deduct** (`debit`) a dollar amount (`$`) on either the **Credit Balance** pool or the **Included Usage** pool, with a required reason recorded in the ledger.
- **On-Demand Usage Limit**: Configure the user's per-period on-demand spending limit (`Off`, `$25`, `$50`, `$100`, `$500`, `Unlimited`, or custom amount) when the account is managed internally, and configure accounting setting locks.

The **Storage** tab shows current storage usage, effective limit, manual override state, and any active storage grace deadline. Set an explicit storage cap in **MB**, **GB**, or **TB**, or apply `0` to return the account to its automatic plan limit.

See [Usage And Costs](/pages/admin/usage-and-billing) before changing balances, limits, or paid usage.

### Roles

The **Roles** tab shows current system and tenant roles (`system_admin`, `system_support`, `system_billing`, `tenant_admin`, `tenant_support`, `tenant_billing`) and supports assigning or removing roles. System-role changes require system-administrator access.

An account can have one system role and one tenant role. Assigning another role in the same scope replaces the current role rather than adding a second role in that scope.

Davinci prevents removal, deactivation, or deletion of the final active system administrator. Promote and verify another administrator before changing the final recovery account.

### Projects

The **Projects** tab separates:

- **Owned Projects**
- **Shared Projects**
- **Deleted Projects** still within their recovery window, which can be restored or permanently deleted. See [Projects, Organizations, And Tenants](/pages/admin/resources-and-tenants#deleted-projects).

## Authentication Recovery

### Reset A Password

Choose whether to email a new temporary password or display it for manual delivery. Resetting invalidates the previous password but does not by itself revoke active sessions. Revoke sessions separately when the recovery is security-related.

### Reset MFA

Resetting MFA disables the user's current enrollment. The user must enroll again according to the deployment's MFA policy.

### Unlink LDAP

Unlinking removes the account's directory association. If LDAP was the only sign-in method, Davinci creates password access and provides a temporary password so the account is not left without a sign-in method.

This action is permanent for the existing link. Use it when an account was linked incorrectly, the directory entry was removed, or LDAP is being retired.

### Switch Existing Users To LDAP

The LDAP migration workflow is available from [System Settings](/pages/admin/system-settings-authentication#switch-existing-users-to-ldap). It verifies each selected user against the directory before switching authentication. Users without a matching directory entry are skipped without changing their current sign-in method.

## Account Lifecycle

### Deactivate

Deactivation revokes active sessions and Design Engine access, cancels the user's subscription, and marks the account suspended while retaining the record for possible reactivation. Review billing and owned resources before using it.

### Reactivate

Reactivation requires selecting an authentication method (**Password**, **OAuth**, **SSO / OIDC**, or **LDAP / Directory**). Password reactivation creates a temporary password and can deliver it by email.

### Permanently Delete

Permanent deletion (`Delete Forever`) removes the user and associated data and requires typing the confirmation text shown by the panel.

<Warning>
Permanent user deletion cannot be undone. Review owned projects, billing, storage, and organization responsibilities before deleting the account. Use deactivation when retention or transfer work is incomplete.
</Warning>
