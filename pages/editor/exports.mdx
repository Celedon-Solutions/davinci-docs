## Overview

Davinci supports several export paths from the Editor. Use exports to archive project state, share project data, integrate with external tools, or publish model content for review.

Exports are available from Project Settings and from supported object or project menus.

## Export Formats

| Format | Use for | Notes |
| --- | --- | --- |
| `.DAF` | Davinci archive and transfer | Preserves model objects and uploaded reference files. Best for round-tripping between Davinci environments. |
| `JSON` | Raw project/model data | Exports model data without uploaded reference files. Useful for inspection and tooling. |
| `SysML v2` | Systems engineering interchange | Exports a standards-oriented `.sysml` representation with export-only transformations. |
| `SysML v2 JSON` | Structured SysML-oriented analysis | Exports structured JSON for workflows that need machine-readable SysML-style data. |
| Document/table/presentation exports | Artifact sharing | Available from supported artifact views. |
| `ZIP` | Package contents as files | Available from the Export menu on a package. Downloads every reference file and code object under the package, with nested packages as folders. |

## SysML Exports

SysML exports are not a raw dump of the Davinci model. Davinci applies export-only transformations to make the output more valid, readable, and useful in downstream tools.

See [SysML v2 Export](/pages/modeling/overview/sysml-export) for detailed mapping behavior, supported object types, limitations, validation behavior, and JSON export details.

## Choosing A Format

- Use `.DAF` when you want to preserve a project for another Davinci environment.
- Use `ZIP` on a package when you want all of its reference files, such as the output of a code analysis, in one download.
- Use JSON when you need model data for custom tooling.
- Use SysML v2 when you need standards-oriented system-model interchange.
- Use artifact exports when sharing human-readable documents, tables, or presentations.

## Exporting Without The Menu

The project agent and API callers can export an object in any format its Export menu offers, for example a document as PDF or DOCX, slides as PPTX, or a table as XLSX. The file is the one the menu produces, with the same styles, page size, and headers and footers, and it is saved to the project as a reference next to the object. PDF exports also report their page count, so you can check that a document fits on the pages it should.

- **Agent:** ask the agent to export the object. It uses the `ExportObject` tool in the References toolbox.
- **API:** call `POST /api/v2/projects/{projectId}/objects/{objectId}/exports` with a `format`, or `client.content.exportObject` in the TypeScript SDK (`client.content.export_object` in Python). The response carries the saved file's id and a `contentUrl` to download it.

These exports run on the server, in the same exporters as the Export menu, so nobody needs the project open. Print PDF is only available from the menu, because it ends in the browser's print dialog.
